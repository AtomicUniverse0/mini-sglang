在前面的内容中，我们已经从调度器层面了解了在Prefill阶段，从开始调度到处理推理结果的全过程，但笔者当时留了一个大坑，

## 模型的初始化
推理模型的初始化是在Engine的构造函数里执行的

### torch.device("meta") 和 torch_dtype(config.type)

`torch.device("meta")` 我们是第一次见，meta 是 PyTorch 的一种只保存元数据、不保存实际数据的设备。
譬如，
```python
    with torch.device("meta"):
    weight = torch.empty(4096, 4096)
```
这个张量会被创建在 meta 设备上，而不是 CPU 或 CUDA，它拥有shape, dtype, stride, requires_grad, device 
等成员变量，但不会真正分配存储空间。

在mini-sgl中，按照模型配置构造出完整的模型结构，避免构造阶段在 CPU/CUDA 上分配和初始化一份无用的参数，随后通过
load_state_dict 把真正的权重替换进去

而 torch_dtype 的源码则十分简单，它将系统默认的浮点类型替换为配置的浮点类型，并在退出上下文管理器后返回。
```python
@contextmanager
  def torch_dtype(dtype: torch.dtype):
      import torch

      old_dtype = torch.get_default_dtype()
      torch.set_default_dtype(dtype)
      try:
          yield
      finally:
          torch.set_default_dtype(old_dtype)
```

### 模型参数的加载
这部分分为 `load_state_dict` 和 `_load_weight_state_dict` 两个部分来讲解。
#### _load_weight_state_dict
```python
class Engine:
    def _load_weight_state_dict(self, config: EngineConfig) -> Dict[str, torch.Tensor]:
        if config.use_dummy_weight:
            return {
                k: torch.randn_like(v, device=self.device)
                for k, v in self.model.state_dict().items()
            }
        else:
            return {k: v.to(self.dtype) for k, v in load_weight(config.model_path, self.device)}
```

`_load_weight_state_dict` 根据配置来随机初始化模型权重或者从指定位置加载权重。 `state_dict`这个函数大家想必
不陌生，不过需要注意的是，mini-sgl里的模型并不是继承于Pytroch里的Module类，而是项目自定义的`BaseOp`类。，因此`state_dict`
也是这个项目自己实现的函数，并非来自Pytorch

```python
class BaseOP:
    def state_dict(self, *, prefix: str = "", result: _STATE_DICT | None = None) -> _STATE_DICT:
        result = result if result is not None else {}

        for name, param in self.__dict__.items():
            if name.startswith("_"):
                continue
            if isinstance(param, torch.Tensor):
                result[_concat_prefix(prefix, name)] = param 
            elif isinstance(param, BaseOP):
                param.state_dict(prefix=_concat_prefix(prefix, name), result=result)

        return result
```

#### load_weight
```python
def load_weight(model_path: str, device: torch.device) -> Iterator[Tuple[str, torch.Tensor]]:
    """Streaming weight loader. Yields (name, tensor) pairs already sharded, merged,
    and on device. Peak CPU memory: one full tensor + a small merge buffer."""
    from .config import ModelConfig

    model_folder = download_hf_weight(model_path) # 从hugging face 下载指模型
    config = ModelConfig.from_hf(cached_load_hf_config(model_path)) # 根据模型来初始化ModelConfig
    files = glob.glob(f"{model_folder}/*.safetensors") # glob 是一个python标准库的一部分，用于根据通配符来读取对应的文件。
                                                    # safetensors 是一种用于保存深度学习模型张量的文件格式，相比PyTorch .bin 或 .pt 文件，safetensors加载速度较快，支持内存映射

    # consolidated.safetensors 是某些模型格式中的合并权重文件。此项目希望优先使用分片权重，因为分片文件更适合流式读取或并行加载
    # 分片过程类似于: 第 1 个文件，embedding前若干层 Transformer, 第 2 个文件： 中间若干层 Transformer，第 3 个文件：后面的 Transformer 层 lm_head 其他参数
    files = [f for f in files if not f.endswith("consolidated.safetensors")] or files
    tp_info = get_tp_info()

    # Buffer for merge groups: merged_key -> {slot: tensor}
    merge_buf: Dict[str, Dict[str, torch.Tensor]] = {}
    expert_buf: Dict[str, Dict[int, torch.Tensor]] = {} # 用于收集 MOE 模型中的多个 expert
    for file in tqdm(files, desc="Loading weights", disable=not tp_info.is_primary()):
        with safetensors.safe_open(file, framework="pt", device=str(device)) as f:
            for name in f.keys():
                # 跳过视觉模块的加载，这说明这个 mini-sglang 只支持语言模型。
                if name.startswith(("vision_tower.", "multi_modal_projector.")):
                    continue
                raw = f.get_tensor(name)
                name = name.removeprefix("language_model.")
                tensor = _shard_tensor(name, raw, tp_info.rank, tp_info.size, config.num_kv_heads)
                del raw

                if (info := _get_merge_info(name)) is None:
                    out = (name, tensor)
                else:
                    merged_key, slot, all_slots = info
                    merge_buf.setdefault(merged_key, {})[slot] = tensor
                    if not all(s in merge_buf[merged_key] for s in all_slots):
                        continue
                    parts = [merge_buf[merged_key][s] for s in all_slots]
                    del merge_buf[merged_key]
                    out = (merged_key, torch.cat(parts, dim=0))

                if config.is_moe and (expert_info := _get_expert_stack_info(out[0])) is not None:
                    packed_key, expert_idx = expert_info
                    slots = expert_buf.setdefault(packed_key, {}) # slots 对应一个专家组，内部有好多个小专家
                    slots[expert_idx] = out[1]
                    if len(slots) != config.num_experts:
                        continue
                    experts = [slots[idx] for idx in range(config.num_experts)]
                    del expert_buf[packed_key]
                    yield packed_key, torch.stack(experts, dim=0)
                else:  # Normal dense model
                    yield out[0], out[1]

    assert not merge_buf, f"Incomplete merge groups in checkpoint: {list(merge_buf.keys())}"
    assert not expert_buf, f"Incomplete expert tensors in checkpoint: {list(expert_buf.keys())}"
```
`load_weight`会遍历模型的每一个 `safetensors` 文件，对读取到的Tensor进行分片处理，`_shard_tensor`无疑是TP的核心。
我们仔细查看一下 `_shard_tensor` 的源码

##### _shard_tensor
```python
_SPLIT_DIM_0 = [".q_proj", ".k_proj", ".v_proj", ".gate_proj", ".up_proj"] # 这几个层一般用于按行切分
_SPLIT_DIM_1 = [".o_proj", ".down_proj"]

# ".q_proj", ".k_proj", ".v_proj", ".o_proj" 是 attention 块的内容
# ".gate_proj", ".up_proj", ".down_proj" 则是 MLP 的内容

# n 是集群中总的节点数量，r是当前节点的id
def _shard_tensor(key: str, value: torch.Tensor, r: int, n: int, num_kv_heads: int):
    """Extract rank r's shard from a single tensor. Returns a contiguous copy."""
    if any(key.count(sub) for sub in _SPLIT_DIM_0):
        is_kv_proj = any(key.count(sub) for sub in (".k_proj", ".v_proj"))
        if is_kv_proj and num_kv_heads is not None and num_kv_heads < n:
            head_dim = value.shape[0] // num_kv_heads
            head_idx = r * num_kv_heads // n
            return value[head_idx * head_dim : (head_idx + 1) * head_dim].clone()
        return value.chunk(n, dim=0)[r].clone()
    elif any(key.count(sub) for sub in _SPLIT_DIM_1):
        return value.chunk(n, dim=1)[r].clone()
    elif key.count("lm_head") or key.count("embed_tokens"):
        num_embeddings = value.shape[0]
        num_embeddings_per_partition = div_ceil(num_embeddings, n)
        vocab_start_idx = r * num_embeddings_per_partition
        vocab_end_idx = min((r + 1) * num_embeddings_per_partition, num_embeddings)
        return value[vocab_start_idx:vocab_end_idx, :].clone()
    else:
        return value
```
简单地讲，上述代码将模型内部的参数矩阵按类型分为3类，这3类按行或者按列进行了划分。看似简单，但细细想来却有许多问题不甚清楚：

1. 以"k_proj"这个矩阵为例子，它的行的含义是？列的含义又是？
2. 为什么 ".q_proj", ".k_proj", ".v_proj", ".gate_proj", ".up_proj" 要按行分， ".o_proj", ".down_proj"要按列分？
3. ".q_proj", ".k_proj", ".v_proj", ".gate_proj", ".up_proj"中，为何偏偏对 `k_proj`和`v_proj`进行特判？

在这里笔者解答第1个问题，剩下的两个问题后文会解答：
PyTorch 的 `nn.Linear(in_features, out_features)` 其权重形状是 `weight.shape = [out_features, in_features]`，`F.linear(X, weight)` 数学上等价于：`Y = X @ weight.T`。
话说，你知道为何要设计成这样吗？为啥不直接创建一个 `[in_features, out_features]`的矩阵，然后计算 `Y = X @ Weight` 呢？(从缓存命中率的角度考虑)
所以，当 `k_proj = nn.Linear( embedding_dim, n_head * head_dim)` 时， `k_proj`底层的矩阵的形状实际上是 `(n_head * head_dim, embedding_dim)`。


**存疑：弄清楚推理引擎与自己手写的Transformer的不同点**
如果你跟着网上的教程手写过Transformer的话，那么`q_proj`,`k_proj`, `v_proj`你肯定不陌生。对于`Decoder Only`的大模型，经过这
3个`proj`后，得到的q, k, v的形状都是 `(batch_size, seq_len, embedding_dim)`，随后进行一次`reshape`变为`(batch_size, seq_len, n_head, head_dim)`，
之后再 `transpose` 成 `(batch_size, n_head, seq_len, head_dim)`，然后进行attention计算，最后会得到一个`(batch_size, n_head, seq_len, head_dim)`的attention结果。
随后，通过`transpose` 和 `reshape` 变回 `(batch_size, seq_len, embedding_dim)`。


##### _get_merge_info
在完成了 Tensor 的切分后，紧接着就会调用 `_get_merge_info`

```python
_MERGE_GROUPS = {
    ".q_proj": (".qkv_proj", ("q", "k", "v")),
    ".k_proj": (".qkv_proj", ("q", "k", "v")),
    ".v_proj": (".qkv_proj", ("q", "k", "v")),
    ".gate_proj": (".gate_up_proj", ("gate", "up")),
    ".up_proj": (".gate_up_proj", ("gate", "up")),
}
_SLOT_NAMES = {
    ".q_proj": "q",
    ".k_proj": "k",
    ".v_proj": "v",
    ".gate_proj": "gate",
    ".up_proj": "up",
}

def _get_merge_info(key: str):
    """If key belongs to a merge group, return (merged_key, slot, all_slots). Else None."""
    for suffix, (fused_suffix, slots) in _MERGE_GROUPS.items():
        if key.count(suffix):
            return key.replace(suffix, fused_suffix), _SLOT_NAMES[suffix], slots
    return None
```
代码逻辑简短，很容易就能看懂。这段代码是为了把 checkpoint 中**分开保存的权重**合并成运行时实现所需要的**融合权重**
譬如，`q_proj.shape = (q_head_dim, input_dim), k_proj.shape = (k_head_dim, input_dim), v_proj.shape = (v_head_dim, input_dim)`
那么融合成的 `qkv_proj` 的 `shape` 就是 `(q_head_dim + k_head_dim + v_head_dim), input_dim`


##### moe处理

完成对部分参数矩阵的融合后，如果一个模型不是 moe 架构的，那么直接返回 out 就可以了，但如果是moe架构的，则需要将各个专家的
权重堆叠在一起。

```python
_EXPERT_PATTERN = re.compile(r"^(?P<prefix>.+\.experts)\.(?P<idx>\d+)\.(?P<name>.+)$")

#被匹配的数据类似于:
# model.layers.0.mlp.experts.0.gate_proj.weight
# model.layers.0.mlp.experts.0.up_proj.weight
# model.layers.0.mlp.experts.0.down_proj.weight

# model.layers.0.mlp.experts.1.gate_proj.weight
# model.layers.0.mlp.experts.1.up_proj.weight
# model.layers.0.mlp.experts.1.down_proj.weight

# r"^(?P<prefix>.+\.experts)\.(?P<idx>\d+)\.(?P<name>.+)$"
# 定义了 3 个命名组：prefix：匹配类似 foo.experts, idx：匹配专家id, name：匹配最后的名称
# 例如：key = "model.layers.0.mlp.experts.0.gate_proj.weight", match = _EXPERT_PATTERN.match(key)
# 结果：
# match.group("prefix")  # "model.layers.0.mlp.experts"
# match.group("idx")     # "0"
# match.group("name")    # "gate_proj.weight"

def _get_expert_stack_info(key: str) -> tuple[str, int] | None:
    """Map an expert-scoped checkpoint key to the packed runtime key."""
    match = _EXPERT_PATTERN.match(key)
    if match is None:
        return None

    packed_name = match.group("name")
    if packed_name.endswith(".weight"):
        packed_name = packed_name.removesuffix(".weight")
    return f"{match.group('prefix')}.{packed_name}", int(match.group("idx"))
```

#### load_state_dict

通过前面 `load_weight` 可知，`load_state_dict` 进行了张量切分，张量融合等过程，返回了一个参数的字典。
下面的 `load_state_dict` 就是将自己的参数设置成对 `load_weight` 里的Tensor
```python
class BaseOp:
    def load_state_dict(
        self,
        state_dict: _STATE_DICT,
        *,
        prefix: str = "",
        _internal: bool = False,
    ) -> None:
        for name, param in self.__dict__.items():
            if name.startswith("_"):
                continue
            if isinstance(param, torch.Tensor):
                item = state_dict.pop(_concat_prefix(prefix, name))
                assert isinstance(item, torch.Tensor)
                assert param.shape == item.shape and param.dtype == item.dtype
                setattr(self, name, item)
            elif isinstance(param, BaseOP):
                param.load_state_dict(
                    state_dict, prefix=_concat_prefix(prefix, name), _internal=True
                )

        if not _internal and state_dict:
            raise RuntimeError(f"Unexpected keys in state_dict: {list(state_dict.keys())}")
```

从这段代码可以推断出，看样子模型自己在进行初始化时，也把自己的参数设置成了切分后的形状

## 模型的 forward
回忆一下前文，模型的`forward`方法是在 Engine 的 `forward_batch` 里开始的。
```python
class Engine:
    def forward_batch(self, batch: Batch, args: BatchSamplingArgs) -> ForwardOutput:
        assert torch.cuda.current_stream() == self.stream
        with self.ctx.forward_batch(batch):
            if self.graph_runner.can_use_cuda_graph(batch):
                logits = self.graph_runner.replay(batch)
            else:
                logits = self.model.forward()

        for req in batch.reqs:
            req.complete_one()

        next_tokens_gpu = self.sampler.sample(logits[: batch.size], args).to(torch.int32)
        next_tokens_cpu = next_tokens_gpu.to("cpu", non_blocking=True)
        copy_done_event = torch.cuda.Event()
        copy_done_event.record(self.stream)
        return ForwardOutput(next_tokens_gpu, next_tokens_cpu, copy_done_event)
```
我们以 `Qwen3MoeForCausalLM` 为例来分析它的forward过程。

先来简单看一眼`Qwen3MoeForCausalLM`的结构，对它有个大概印象:

`Qwen3Model`是它是 Qwen3 的 Transformer 主体,而`ParallelLMHead`负责把 Qwen3Model 输出的隐藏向量转换成整个词表上的 logits

### Qwen3Model 的构成
```python
class Qwen3Model(BaseOP):
    def __init__(self, config: ModelConfig):
        self.embed_tokens = VocabParallelEmbedding(
            num_embeddings=config.vocab_size,
            embedding_dim=config.hidden_size,
        )
        self.layers = OPList(
            [Qwen3DecoderLayer(config, layer_id) for layer_id in range(config.num_layers)]
        )
        self.norm = RMSNormFused(
            size=config.hidden_size,
            eps=config.rms_norm_eps,
        )

    def forward(self, input_ids: torch.Tensor) -> torch.Tensor:
        x = self.embed_tokens.forward(input_ids)
        residual: torch.Tensor | None = None
        for layer in self.layers.op_list:
            x, residual = layer.forward(x, residual)
        return self.norm.forward(x, residual)[0]
```

#### VocabParallelEmbedding
果然，`VocabParallelEmbedding` 在初始化自己的 weight 时，就考虑了张量并行
```python
class VocabParallelEmbedding(BaseOP):
    def __init__(
        self,
        num_embeddings: int, # 词表大小
        embedding_dim: int,
    ):
        super().__init__()
        tp_info = get_tp_info()
        tp_rank = tp_info.rank
        self.tp_size = tp_info.size
        self.num_embeddings = num_embeddings
        self.num_embeddings_tp = div_ceil(num_embeddings, self.tp_size)
        start_idx = self.num_embeddings_tp * tp_rank
        finish_idx = min(start_idx + self.num_embeddings_tp, num_embeddings)
        self.vocab_range = (start_idx, finish_idx - start_idx)
        # 结合num_embeddings_tp的来源可知，这个 weight 是被TP之后的
        self.weight = torch.empty(self.num_embeddings_tp, embedding_dim) 
        self._comm = DistributedCommunicator() # 底层还是基于 pytorch 的 distributed 来做通信的

    @nvtx_annotate("Embedding")
    def forward(self, x: torch.Tensor) -> torch.Tensor:
        from minisgl.kernel import indexing

        y = indexing(
            weights=self.weight,
            indices=x,
            vocab_range=self.vocab_range if self.tp_size > 1 else None,
        )

        return self._comm.all_reduce(y) if self.tp_size > 1 else y
```

`forward` 中的 `indexing` 底层也是调用了一个 cpp 函数:
```python
def indexing(
    weights: torch.Tensor,
    indices: torch.Tensor,
    *,
    output: torch.Tensor | None = None,
    vocab_range: Tuple[int, int] | None = None,  # (start, length)
) -> torch.Tensor:
    if output is None:
        output = weights.new_empty(indices.shape[0], weights.shape[1])

    element_size = weights.shape[1] * weights.element_size()
    if element_size % 2048 == 0:
        num_splits = 4
    elif element_size % 1024 == 0:
        num_splits = 2
    else:
        num_splits = 1
    module = _jit_index_module(element_size, num_splits=num_splits) # 以 <element_size, num_splits> 为模板参数初始化了 indexing 类
    module.launch(weights, indices, output, vocab_range)
    return output

```
不妨假设 element_size 是4，即 float32，那么当一个embedding的长度是512的倍数时，用128个线程来搬运它，否则，如果是256的倍数，则用64个来，如果都不是，就用32个来搬运
`IndexKernel` 的 `run` 在 cpu 侧执行，它会进行参数校验，并决定调用哪个 Cuda 核函数
```cpp
template <std::size_t element_size,   // depends on data type and embedding dim
          std::size_t num_splits = 1, // how many warps handles one element
          std::size_t num_threads = 128,   // number of threads per block
          std::size_t max_concurrency = 1, // max blocks per SM
          bool use_pdl = false>
struct IndexKernel {
  static void run(const tvm::ffi::TensorView weights,
                  const tvm::ffi::TensorView indices,
                  const tvm::ffi::TensorView output,
                  tvm::ffi::Optional<tvm::ffi::Tuple<int, int>> mask_opts) {
    using namespace host;

    // 省略大量的参数检查逻辑

    constexpr auto kWarpPerBlock = num_threads / 32;
    const auto num_warps = num_splits * num_indices; // num_indices 是所有 token 的数量
    const auto num_blocks = div_ceil(num_warps, kWarpPerBlock);
    const auto params = IndexKernelParams{
        .output = static_cast<char *>(output.data_ptr()),
        .weight = static_cast<const char *>(weights.data_ptr()),
        .indice = indices.data_ptr(),
        .num_warps = num_warps,
    };

    // mask_opts 有值，说明启动了张量并行， 此时 mask_opts 代表当前 rank 负责的 token id 的范围
    if (mask_opts.has_value()) {
      const auto &obj = mask_opts.value();
      const auto [start, length] = obj;
      const auto m_params = MaskedKernelParams{
          .params = params,
          .start = static_cast<std::size_t>(start),
          .length = static_cast<std::size_t>(length),
      };
      const auto kernel =
          use_int32 ? masked_index_kernel<num_threads, max_concurrency, use_pdl,
                                          element_size, num_splits, int32_t>
                    : masked_index_kernel<num_threads, max_concurrency, use_pdl,
                                          element_size, num_splits, int64_t>;
      LaunchKernel(num_blocks, num_threads, device)
          .with_attr(use_pdl)(kernel, m_params);
    } else {
      const auto kernel =
          use_int32 ? index_kernel<num_threads, max_concurrency, use_pdl,
                                   element_size, num_splits, int32_t>
                    : index_kernel<num_threads, max_concurrency, use_pdl,
                                   element_size, num_splits, int64_t>;
      LaunchKernel(num_blocks, num_threads, device)
          .with_attr(use_pdl)(kernel, params);
    }
  }
};
```
启动张量并行时，主要使用的是 `masked_index_kernel`
```cpp
template <std::size_t kNumThreads, std::size_t kMaxOccupancy, bool kUsePDL,
          std::size_t kElementSize, std::size_t kNumSplits, std::integral T>
__global__ __launch_bounds__(kNumThreads, kMaxOccupancy) void //
    masked_index_kernel(
        const __grid_constant__ MaskedKernelParams mask_params) {
  using namespace device;
  constexpr auto kSize = kElementSize; // 每个embedding的字节数
  constexpr auto kSizePerWarp = kSize / kNumSplits;
  constexpr auto kWarpPerBlock = static_cast<unsigned>(kNumThreads / 32);

  static_assert(kNumThreads % 32 == 0);
  static_assert(std::has_single_bit(kNumSplits));
  static_assert(kElementSize % kNumSplits == 0);

  const auto &[params, start, length] = mask_params;
  const auto &[output, weight, indices_, num_warps] = params;
  const auto indices = static_cast<const T *>(indices_);
  const auto warp_id =
      (threadIdx.x / kWarpThreads) + blockIdx.x * kWarpPerBlock;

  PDL::wait<kUsePDL>();

  if (warp_id < num_warps) {
    const auto pos = indices[warp_id / kNumSplits] - start;
    const auto dst = pointer::offset(output, warp_id * kSizePerWarp);
    if (pos < length) {
      const auto src = pointer::offset(weight, pos * kSize,
                                       (warp_id % kNumSplits) * kSizePerWarp);
      warp::copy<kSizePerWarp>(dst, src);
    } else {
      warp::reset<kSizePerWarp>(dst);
    }
  }

  PDL::launch<kUsePDL>();
}
```

##### RMSNormFused
```python
class RMSNormFused(BaseOP):
    def __init__(self, size: int, eps: float) -> None:
        from flashinfer import fused_add_rmsnorm, rmsnorm

        self.eps = eps
        self.weight = torch.empty(size)
        self.rmsnorm = rmsnorm # rmsnorm 和 fused_add_rmsnorm 都来自 flashinfer 包
        self.fused_add_rmsnorm = fused_add_rmsnorm

    def forward(
        self, x: torch.Tensor, residual: torch.Tensor | None = None
    ) -> Tuple[torch.Tensor, torch.Tensor]:
        if residual is None:
            return self.rmsnorm(x, self.weight, self.eps), x
        self.fused_add_rmsnorm(x, residual, self.weight, self.eps)
        return x, residual
```
`RMSNorm` 对隐藏向量 (x) 的最后一个维度进行归一化：

$$
\operatorname{RMSNorm}(x) = 

\frac{x}{\sqrt{\operatorname{mean}(x^2)+\epsilon}}
\odot w
$$

其中：

- mean(x²)：隐藏维度上所有元素平方后的均值
- eps：防止除零、提高数值稳定性
- weight：可学习的缩放参数

和 LayerNorm 
$$
\frac{(x - mean(x)) } {sqrt(var(x) + eps)} * weight + bias
$$
相比，RMSNorm 不减去均值,计算更简单

RMSNorm 已被大量现代模型采用，例如 LLaMA、Mistral、Qwen 等。实践表明，在 Pre-Norm Transformer 中，模型主要需要控制隐藏状态的整体尺度,**只进行尺度归一化已经足够**，而均值中心化往往不是必需的

```python
class RotaryEmbedding(StateLessOP):
    def __init__(
        self,
        head_size: int,
        rotary_dim: int,
        max_position_embeddings: int,
        base: float,
        post_process: None | Callable[[torch.Tensor], torch.Tensor] = None,
    ) -> None:
        super().__init__()
        self.head_size = head_size
        assert rotary_dim == head_size
        inv_freq = 1.0 / (base ** (torch.arange(0, rotary_dim, 2, dtype=torch.float) / rotary_dim))
        if post_process is not None:
            inv_freq = post_process(inv_freq)
        t = torch.arange(max_position_embeddings, dtype=torch.float)
        freqs = torch.einsum("i,j -> ij", t, inv_freq)
        cos = freqs.cos()
        sin = freqs.sin()
        # buffer, so don't load/save
        self._cos_sin_cache = torch.cat((cos, sin), dim=-1)
        assert self.head_size in [64, 128, 256, 512]

        from flashinfer import apply_rope_with_cos_sin_cache_inplace

        self.apply_rope_with_cos_sin_cache_inplace = apply_rope_with_cos_sin_cache_inplace

    def forward(
        self,
        positions: torch.Tensor,
        query: torch.Tensor,
        key: torch.Tensor,
    ) -> Tuple[torch.Tensor, torch.Tensor]:
        self.apply_rope_with_cos_sin_cache_inplace(
            positions=positions,
            query=query,
            key=key,
            head_size=self.head_size,
            cos_sin_cache=self._cos_sin_cache,
        )
        return query, key
```

```python
class AttentionLayer(StateLessOP):
    def __init__(
        self,
        layer_id: int,
        num_qo_heads: int,
        num_kv_heads: int,
        head_dim: int,
        rotary_config: RotaryConfig,
        q_norm: RMSNorm | None = None,
        k_norm: RMSNorm | None = None,
    ):
        assert num_qo_heads % num_kv_heads == 0
        self.layer_id = layer_id
        self.head_dim = head_dim
        tp_size = get_tp_info().size
        self.num_qo_heads = div_even(num_qo_heads, tp_size) # num_qo_heads % tp_size  == 0 一定成立。一般 GQA 和 MQA 里Q头的数量远大于 K 和 V
        self.num_kv_heads = div_even(num_kv_heads, tp_size, allow_replicate=True)
        self.qo_attn_dim = self.num_qo_heads * head_dim
        self.kv_attn_dim = self.num_kv_heads * head_dim
        self.rotary = get_rope( # 获得rope层
            head_dim=head_dim,
            rotary_dim=rotary_config.rotary_dim,
            max_position=rotary_config.max_position,
            base=rotary_config.base,
            rope_scaling=tuple(rotary_config.scaling.items()) if rotary_config.scaling else None,
        )
        self.q_norm = q_norm
        self.k_norm = k_norm

    def forward(self, qkv: torch.Tensor) -> torch.Tensor:
        ctx = get_global_ctx()
        # q, k, v 的形状应该是二维的，[ size, num_head * head_dim ]
        q, k, v = qkv.split([self.qo_attn_dim, self.kv_attn_dim, self.kv_attn_dim], dim=-1)
        if self.q_norm is not None:
            self.q_norm.forward_inplace(q.view(-1, self.num_qo_heads, self.head_dim))
        if self.k_norm is not None:
            self.k_norm.forward_inplace(k.view(-1, self.num_kv_heads, self.head_dim))
        q, k = self.rotary.forward(ctx.batch.positions, q, k)
        q = q.view(-1, self.num_qo_heads, self.head_dim)
        o = ctx.attn_backend.forward(q, k, v, self.layer_id, ctx.batch) # 啊哈，原来在这里调用了 attn_backend!
        return o.view(-1, self.qo_attn_dim)
```

MoELayer的代码如下:
```py
class MoELayer(BaseOP):
    def __init__(
        self,
        num_experts: int,
        top_k: int,
        hidden_size: int,
        intermediate_size: int,
        renormalize: bool = True,
        activation: str = "silu",
        apply_router_weight_on_input: bool = False,
    ):
        super().__init__()

        self.num_experts = num_experts
        self.top_k = top_k
        self.hidden_size = hidden_size
        self.intermediate_size = intermediate_size
        self._comm = DistributedCommunicator()

        tp_info = get_tp_info()
        self.tp_size = tp_size = tp_info.size
        self.renormalize = renormalize
        self.activation = activation
        self.apply_router_weight_on_input = apply_router_weight_on_input
        intermediate_size_per_partition = div_even(intermediate_size, tp_size)
        self.gate_up_proj = torch.empty(
            num_experts,
            2 * intermediate_size_per_partition,
            hidden_size,
        )
        self.down_proj = torch.empty(
            num_experts,
            hidden_size,
            intermediate_size_per_partition,
        )

    def forward(self, hidden_states: torch.Tensor, router_logits: torch.Tensor):
        ctx = get_global_ctx()
        final_hidden_states = ctx.moe_backend.forward(
            hidden_states=hidden_states,
            w1=self.gate_up_proj,
            w2=self.down_proj,
            gating_output=router_logits,
            topk=self.top_k,
            renormalize=self.renormalize,
            activation=self.activation,
            apply_router_weight_on_input=self.apply_router_weight_on_input,
        )
        if self.tp_size > 1:
            final_hidden_states = self._comm.all_reduce(final_hidden_states)
        return final_hidden_states
```

它持有两个TP后的重要参数:
1. `gate_up_proj` : (num_experts, 2 * intermediate_size_per_partition, hidden_size)
2. `down_proj` : (num_experts, hidden_size, intermediate_size_per_partition)
然后，它调用 `moe_backend` 进行了moe的计算。

```python
def fused_topk(
    hidden_states: torch.Tensor, # [num_token, hidden_size]
    gating_output: torch.Tensor, # [num_token, expert_num]
    topk: int, #  topk <= expert_num
    renormalize: bool,
    num_token_non_padded: torch.Tensor | None = None, # None
) -> Tuple[torch.Tensor, torch.Tensor]:
    from sgl_kernel import topk_softmax

    assert hidden_states.shape[0] == gating_output.shape[0], "Number of tokens mismatch"
    M, _ = hidden_states.shape
    topk_weights = torch.empty(M, topk, dtype=torch.float32, device=hidden_states.device)
    topk_ids = torch.empty(M, topk, dtype=torch.int32, device=hidden_states.device)
    topk_softmax(topk_weights, topk_ids, gating_output.float(), renormalize)
    # topk_softmax 的语义是， 对 gating_output.float() 做 softmax，然后选出 topk 的值，以及值对应的下标
    # 如果 renormalize = true，则对选出的 topk 值做归一化

    # if renormalize: 冗余逻辑， topk_softmax 里面本身就有了
    #     topk_weights = topk_weights / (topk_weights.sum(dim=-1, keepdim=True) + 1e-8)
    if num_token_non_padded is not None:
        indices = torch.arange(0, topk_ids.shape[0], device=topk_ids.device)
        topk_ids[indices >= num_token_non_padded, :] = -1
    return topk_weights, topk_ids
```

```python
def moe_align_block_size(
    topk_ids: torch.Tensor, block_size: int, num_experts: int
) -> Tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
    """
    Example:
    Given topk_ids = [[2, 3, 4], [1, 2, 4], [1, 3, 4], [1, 2, 3]],
    block_size = 4, and num_experts = 4:
    - We initially have 12 tokens (after repeating 'top_k' times) and 4 experts,
        with each expert needing to process 3 tokens.
    - As block_size is 4, we pad 1 token for each expert.
    - First, flatten topk_ids to [2, 3, 4, 1, 2, 4, 1, 3, 4, 1, 2, 3].
    - Then append padding tokens [12, 12, 12, 12] for each block.
    - After sorting by expert index, we obtain token_ids
        [3, 6, 9, 12, 0, 4, 10, 12, 1, 7, 11, 12, 2, 5, 8, 12].
        Tokens 12 are non-existent (padding) and are ignored in
        the subsequent matrix multiplication.
    - The padding ensures that the total number of tokens is now divisible
        by block_size for proper block matrix operations.
    """
    from sgl_kernel import moe_align_block_size as sgl_moe_align_block_size

    # numel 即 number of elements
    max_num_tokens_padded = topk_ids.numel() + (num_experts + 1) * (block_size - 1)
    sorted_ids = torch.empty((max_num_tokens_padded,), dtype=torch.int32, device=topk_ids.device) # 存放按 expert 分组后的展平路由索引。
    max_num_m_blocks = div_ceil(max_num_tokens_padded, block_size)
    # 每个 expert 都刚好占一个 block，expert_ids 是指每个 block 对应的 expert id
    expert_ids = torch.empty((max_num_m_blocks,), dtype=torch.int32, device=topk_ids.device) 
    num_tokens_post_pad = torch.empty((1), dtype=torch.int32, device=topk_ids.device) # 补白后的 token 总数
    cumsum_buffer = torch.empty((num_experts + 2,), dtype=torch.int32, device=topk_ids.device) # 这是底层 kernel 使用的临时工作区，它不需要返回给调用者
    sgl_moe_align_block_size(
        topk_ids,
        num_experts + 1,
        block_size,
        sorted_ids,
        expert_ids,
        num_tokens_post_pad,
        cumsum_buffer,
        True,
    )
    return sorted_ids, expert_ids, num_tokens_post_pad
```

# 问题整理
读完了上面的代码，我们至少要对如下问题的答案了然于心

## Qwen3Moe 的结构是怎样的？假如是在单机上，这些组成元素各自的矩阵形状是多少？输入的形状是啥，输出的形状又是啥？
### Qwen3Moe 的结构
这个模型由两部分组合而成，分别是模型本体和一个外层的还原矩阵

模型本体由一个 embedding矩阵，若干个decoderLayer，以及一个RMSNorm 组成。

DecoderLayer是由一个 RMSNorm, 一个自注意力，一个 RMSNorm，一个 MOEMLP 组成的。

而外层的还原矩阵本质上是个很大的线性层

### 单机上元素各自的矩阵

VocabParallelEmbedding 层 : [vocab_size, hidden_dim]

Decoder::RMSNorm: [hidden_size, 1]

Decoder::Atten::QKVLinear: [(num_head_q + 2 * num_head_kv) * hidden_size, hidden_size]
Decoder::Atten::AttenLayer: 无参数
Decoder::Atten::LinearOProj: [hidden_size, num_head_q * hidden_size]

Decoder::RMSNorm: [hidden_size, 1]

Decoder::MoEMLP::MoELayer::down_proj: [num_experts, hidden_size, intermedidate]

ParallelLMHead 层: [vocab_size, hidden_dim]

需要注意的是，上面的矩阵都是真实的物理性状，比如 QKVLinear，它在计算时，是会取转置的: `x @ QKVLinear.T` 这样对缓存更加友好
而且 `VocabParallelEmbedding` 和 `ParallelLMHead` 的功能是反的，可它们的形状居然相同，而不是互为转置。

所以，如果矩阵被用于矩阵乘法的右侧，矩阵最好按照列主序存储。或者行主序的转置

## TP是如何体现在 Qwen3Moe 里面的？

VocabParallelEmbedding 层: 按行切分， [vocab_size // tp, hidden_dim]

Decoder::RMSNorm: [hidden_size, 1]: 矩阵很小，无需切分

Decoder::Atten::QKVLinear: 按行切分，严格地说，是按照head切分, [(num_head_q // tp + 2 * num_head_kv // tp) * hidden_size, hidden_size]
Decoder::Atten::AttenLayer: 无切分，毕竟无参数
Decoder::Atten::LinearOProj: 按列切分，[hidden_size, num_head_q // tp]

Decoder::RMSNorm: [hidden_size, 1] 无切分

Decoder::MoEMLP::LinearReplicated: 无切分，[num_experts, hidden_dim]
Decoder::MoEMLP::MoELayer::gate_up_proj: 每个专家按照行切分， [num_experts, 2 * intermedidate // tp, hidden_size]  
Decoder::MoEMLP::MoELayer::down_proj: 每个专家按照列切分 [num_experts, hidden_size, intermedidate // tp]

ParallelLMHead 层: 按行切分， [vocab_size // tp, hidden_dim]

由上可见，嵌入层和还原层都是按行切分，切 vocab_size
RMSNorm 和 路由矩阵都不切分，而且它们也比较小。
QKVLinear，MoELayer::gate_up_proj，这两个都是按行切分，前者严格来说是按照head来切分
LinearOProj, MoELayer::down_proj，都是按列进行切分

## 整个过程中涉及了几次集合通信？分别在哪个阶段？

VocabParallelEmbedding -> all_reduce

Decoder::RMSNorm -> Decoder::Atten::QKVLinear -> Decoder::Atten::AttenLayer -> Decoder::Atten::LinearOProj -> all_reduce

Decoder::RMSNorm: [hidden_size, 1] -> Decoder::MoEMLP::LinearReplicated -> Decoder::MoEMLP::MoELayer::gate_up_proj -> Decoder::MoEMLP::MoELayer::down_proj -> all_reduce 

ParallelLMHead 层: 按行切分， [vocab_size // tp, hidden_dim] -> all_gather

总结:
假设模型的 Decoder 层数是 D，那么一次推理需要 ( 2 * D + 1 ) 次 all_reduce 和 一次 all_gather
